# Versioning Policy

Yohan.AI menggunakan Semantic Versioning.

Format:

```
MAJOR.MINOR.PATCH
```

Contoh:

```
1.0.0
0.9.2
0.5.14
```

Keterangan:

| Type | Description |
|------|-------------|
| Major | Perubahan besar atau breaking changes |
| Minor | Penambahan fitur baru |
| Patch | Bug fix dan improvement |

## 23 September 2026 — Lead Intake Fase 1 & CRM Foundation Fase 2

Lead intake dari Google Form legacy ke `customer.leads` selesai dan terverifikasi end-to-end di production. CRM Foundation (Lead List, filter, dashboard) menyusul di hari yang sama berdasarkan feedback pemakaian langsung.

### Added

- **`POST /api/leads/intake`** — pintu masuk lead dari Apps Script legacy (`UrlFetchApp.fetch`), diamankan secret header (`LEADS_INTAKE_SECRET`), dedup lewat `metadata->>source_row_ref`. Hanya field mentah form yang diterima — output AI Processor/Decision Engine/Property Matching Engine di spreadsheet legacy sengaja tidak ikut dipindahkan
- `src/lib/supabase/admin.ts` — service-role client untuk route server-to-server tanpa sesi login
- **CRM Lead List** (`/crm`) — baca `customer.leads` asli, pagination, filter tanggal/kategori/temperature/search (nama atau nomor HP), tombol WhatsApp langsung per lead (`wa.me` + pesan pembuka)
- **Lead Funnel** di dashboard — 5 kategori (Hot/Warm/Cold/Closing/Batal, dari `metadata->>status_funnel_awal`), tiap tile bisa diklik dan mengarah ke Lead List terfilter
- **AI Intelligence — 1 insight nyata**: "Follow-up Backlog" (lead Hot/Warm belum di-follow-up >48 jam, dihitung asli dari database, bisa diklik). 2 kartu contoh lain dipertahankan di kode tapi ditandai `isPlaceholder` + badge "Segera hadir", supaya gampang dikembalikan begitu AI Foundation sungguhan dibangun
- Kolom `customer.leads.assigned_to` — kepemilikan CRM per lead, terpisah dari `created_by`/`updated_by` (audit trail)
- Fungsi `core.is_admin_or_above()` dan role `agent` (dari `core.roles`, pertama kali dipakai) untuk kontrol akses bertingkat

### Fixed

- **`service_role` tidak pernah diberi `GRANT USAGE` ke schema `customer`** — endpoint intake sempat balas `permission denied for schema customer` sebelum diperbaiki. Scope grant sengaja dipersempit ke `customer` saja, bukan semua schema domain
- **Lead Funnel selalu 0% untuk semua temperature** — query lama memfilter `leads.status = 'hot'/'warm'/'cold'`, padahal kolom itu pipeline (`new`/.../`won`/`lost`) yang CHECK constraint-nya menolak nilai itu. Temperature asli ada di `metadata->>status_funnel_awal`
- **`created_at` hasil backfill = waktu insert, bukan tanggal submit form asli** — membuat "Today's New Leads" di dashboard selalu sama dengan Total Leads, dan filter tanggal tidak berguna. Diperbaiki di endpoint (parse `submittedAt` jadi `created_at` eksplisit) dan dibenahi retroaktif untuk 1968 lead yang sudah terlanjur masuk
- Kolom "Sumber" di Lead List menampilkan nama lead source (selalu "Google Form", tidak informatif) — diganti `metadata->>sumber_informasi` (Iklan/Baliho/Referral/dll, sesuai data form asli)
- **`authenticated` tidak pernah diberi GRANT ke `chat.conversations`/`chat.messages`** — widget "Recent Chats" selalu balas Error, bukan tampilan kosong yang jujur
- **Policy `authenticated_all` di `customer.leads` membuat SEMUA akun yang login melihat SEMUA lead**, tanpa kecuali. Ditemukan saat sadar ada akun kedua (kolega Yohan di Griya Indonesia) yang otomatis kebagian akses penuh ke 1968 lead. Diganti kebijakan baru: admin/super_admin tetap lihat semua (oversight bisnis), role lain cuma lihat lead yang `assigned_to` dirinya sendiri

### Changed

- Dashboard: Lead Funnel dipindah ke atas (sebelum Recent Leads/Chats), sesuai kebutuhan lihat status follow-up sekilas
- Recent Leads: baris "Source ID" diganti Kategori lead; badge status "new" diganti tombol WhatsApp
- `customer.lead_sources` bertambah satu baris: "Google Form"

## 23 September 2026 — Platform Hold

Project dihentikan sementara dari pengembangan SaaS dan diturunkan ke mode pemakaian personal.

### Added

- Halaman `/under-development` sebagai wajah publik selama hold, dengan `robots: noindex`
- Platform lock (`src/lib/platform-lock.ts`) — gate yang membelokkan seluruh route ke halaman under-development, kecuali login, recovery password, `/callback`, halaman legal, dan `/api/health`
- Env var `PLATFORM_LOCKED`, `NEXT_PUBLIC_PLATFORM_LOCKED`, `PLATFORM_ALLOWED_EMAILS`. Default **terkunci** — platform hanya terbuka bila di-set eksplisit ke `false`
- Blokir registrasi dua lapis: di proxy sekaligus di `register/page.tsx`

### Fixed

- **`middleware.ts` tidak pernah dieksekusi Next.** File berada di root project, padahal project memakai direktori `src/` sehingga Next mencarinya di `src/` sejajar dengan `app/`. Diabaikan tanpa peringatan, akibatnya `updateSession()` tidak pernah jalan dan refresh sesi Supabase lewat middleware tidak pernah aktif sejak awal. Dipindah ke `src/proxy.ts` mengikuti konvensi Next 16 yang mengganti nama `middleware` menjadi `proxy`

### Changed

- Halaman login menampilkan keterangan pendaftaran ditutup, menggantikan tautan Create Account
- Signup dimatikan di level Supabase Auth — lapis aplikasi saja tidak cukup karena `anon key` ada di bundle browser

## Sprint 011 — 20–25 Agustus 2026

Fokus: stabilisasi autentikasi dan penyelesaian modul Profile.

### Added

- **Edit Profile** — form table-driven yang membaca field wajib dari tabel `profile_completeness_rules`, bukan hardcode. Field kondisional muncul otomatis berdasarkan `depends_on_field_key`
- **Cascading wilayah selector** — Provinsi → Kabupaten → Kecamatan → Desa, query per level. Seed 38 provinsi, 514 kabupaten/kota, 7.285 kecamatan, 83.762 desa, tervalidasi silang dengan angka resmi dan nol baris yatim
- **Change Password** — route terpisah dari Forgot Password, wajib re-autentikasi dengan password lama sebelum boleh mengganti. Mencegah pencuri sesi mengunci pemilik akun keluar. Akun Google-only terdeteksi otomatis dan tidak ditampilkan form password
- **Notification Preferences** — tabel `auth_ext.notification_preferences`, empat kategori toggle plus kategori Keamanan Akun yang sengaja tidak bisa dimatikan
- Halaman Privacy Policy dan Data Deletion, mencantumkan nama legal usaha dan NIB
- GitHub Actions scheduled workflow untuk ping Supabase tiap 3 hari, mencegah auto-pause free tier
- Migration `001_edit_profile_schema.sql` — `core.business_roles`, empat tabel wilayah, kolom baru di `auth_ext.profiles`, tabel `profile_completeness_rules`, dan RPC `check_profile_completeness()`

### Fixed

- Profile page mengambil data asli dari `auth_ext.profiles`, menggantikan dummy data Sprint 008
- Schema `auth_ext`, `core`, `customer`, `chat`, `property` belum ter-expose di Supabase Data API — sebelumnya hanya `public` dan `graphql_public` yang aktif
- `GRANT SELECT/UPDATE` untuk role `authenticated` belum diberikan pada `auth_ext.profiles` dan `core.business_roles`. Policy RLS sudah benar, tapi grant dasar di bawahnya belum ada — dua lapisan berbeda di Postgres
- CSS variable `--popover` dan `--popover-foreground` tidak pernah didefinisikan di `tokens.css`, membuat seluruh dropdown komponen Select tampil transparan
- MX Record domain `yohanai.id` tidak pernah ada, sehingga semua email masuk ke `admin@yohanai.id` tidak pernah sampai

### Changed

- **SMTP outbound migrasi dari Gmail personal ke Resend.** Domain diverifikasi lewat subdomain khusus `send.yohanai.id` agar email masuk existing via rumahweb tidak terganggu
- SPF, DKIM, dan DMARC aktif untuk `yohanai.id`. DMARC masih mode monitoring (`p=none`)

### Removed

- **Facebook Login dibatalkan permanen.** Meta menolak Business Verification karena NIB terdaftar atas nama usaha pribadi sedangkan "YohanAI" adalah brand di bawahnya. Dibersihkan penuh: `FacebookButton.tsx` dihapus, referensi di form login dan register dihapus, provider dimatikan di Supabase
- Dead code `useLogin.ts` dan `useRegister.ts`
