# Skema Data

**Tabel:** `property.categories` (id, name, description) dan `property.listings` (id, **slug** (unik, migration `042`), category_id, **assigned_to** (kepemilikan per agent, migration `043`), title, description, address, price, **metadata JSONB**, timestamps). Tidak ada tabel `property.images` terpisah — semua field tambahan (spesifikasi + foto) disimpan di kolom `metadata`, mengikuti pola yang sama seperti `customer.leads` (bukan kolom per-field). `slug` sendiri kolom asli (unik, NOT NULL), bukan di metadata, karena dipakai routing URL — dibuat otomatis dari judul saat insert (`src/lib/property/slugify.ts`), ditambah suffix `-2`/`-3` dst kalau ada tabrakan judul.

```json
{
  "status": "available" | "booked" | "sold" | "hold",
  "bedrooms": number | null,
  "bathrooms": number | null,
  "land_area": number | null,
  "building_area": number | null,
  "carport": number | null,
  "certificate_type": "SHM" | "HGB" | "Girik" | "Lainnya" | null,
  "video_url": string | null,
  "contact_phone": string | null,
  "photo_urls": string[]
}
```

`photo_urls[0]` = foto sampul, dipakai di grid list & (rencananya) flyer promosi.

**GRANT:** `authenticated` sebelumnya **0 akses** ke schema `property` (temuan audit 23 September 2026, sengaja belum diperbaiki karena belum ada kode yang butuh) — diperbaiki di migration `041` begitu Property Module mulai dibangun. Storage bucket `properties` sudah ada dari migration `019` (public), tidak perlu bucket baru. **`service_role` juga sempat 0 akses ke schema `property`** (pola yang sama seperti temuan `customer`/`chat` di `AGENTS.md`) — ditemukan 28 September 2026 saat skrip migrasi bulk listing (pakai `service_role` key) gagal dengan "permission denied for schema property", diperbaiki di migration `044`.

**RLS `property.categories`:** policy `authenticated_all` (`USING core.is_authenticated()`) ternyata sudah ada di database sejak awal, tapi **tidak tercatat di migration manapun** di repo — ditemukan 26 September 2026 saat verifikasi sebelum membangun halaman Kelola Kategori (pola yang sama seperti temuan audit 23 September di `AGENTS.md`: isi repo bukan cermin isi database). GRANT `authenticated`: SELECT/INSERT/UPDATE ada (`041`), **DELETE tidak ada** — bukan masalah karena hapus kategori memakai soft delete (`deleted_at`), bukan DELETE asli.

**RLS `property.listings`:** sama seperti `categories`, policy `authenticated_all` yang ada di database sebelum migration `043` juga **tidak pernah tercatat di file migration manapun** — ditemukan 27 September 2026 saat verifikasi sebelum membangun kepemilikan per agent. Diganti di `043` jadi policy `listings_owner_or_admin`, identik pola `leads_owner_or_admin` (`035`): admin/super_admin lihat semua, role lain cuma lihat `assigned_to = auth.uid()`. Reuse `core.is_admin_or_above()` dan `core.list_assignable_users()` — tidak ada fungsi baru. Diverifikasi lewat simulasi JWT langsung (bukan cuma baca policy): admin lihat listing, Ramlan (role `agent`, belum ditugaskan listing manapun) lihat 0.

# Current Features

## Property List (`/properties`)

Grid card (foto sampul, judul, harga, badge status), filter status + kategori + pencarian judul/alamat. Pagination 24/48/96 per halaman (`ListingListPagination`/`ListingPageSizeSelect`, pola sama seperti Lead List di CRM) -- `getListings()` di `src/lib/property/getListings.ts` sekarang query dengan `count: "exact"` + `.range()`, bukan ambil semua sekaligus.

## Tambah Listing (`/properties/new`)

Field dasar + spesifikasi standar dalam satu form. Foto ditambahkan setelah listing tersimpan (butuh id listing dulu), lewat halaman detail. Field "Ditugaskan ke" (wajib) cuma tampil untuk admin/super_admin (default assign ke diri sendiri, bisa diganti) — non-admin tidak lihat dropdown-nya sama sekali dan otomatis assign ke diri sendiri, pola identik `AddLeadForm.tsx` di CRM.

## Property Detail (`/properties/[slug]`)

- **Edit Judul/Harga/Alamat/Deskripsi** (28 Sep 2026, `PropertyMainFieldsEditable.tsx`) — tombol Edit/Save/Batal, field kolom asli tabel (bukan metadata), beda komponen dari `PropertyEditableFields` yang cuma edit metadata JSONB.
- **Hapus Listing** (28 Sep 2026) — tombol "Hapus" di sebelah Edit, soft delete (`deleted_at`), konfirmasi `window.confirm`, redirect ke `/properties` setelah berhasil. Belum ada UI pulihkan listing terhapus (beda dari kategori) -- kalau perlu, langsung lewat database.
- Galeri foto dengan tombol tambah/hapus (foto pertama = sampul). Foto baru otomatis diberi **watermark logo Yohan.AI** di tengah (lihat "Watermark Foto" di bawah).
- Video embed (YouTube) kalau ada.
- Spesifikasi inline-editable, termasuk `contact_phone` (pola sama seperti `LeadEditableFields` di CRM).
- "Ditugaskan ke" — dropdown ganti penanggung jawab (`PropertyAssignSelect.tsx`, admin/super_admin saja; non-admin cuma lihat teks statis "Saya"), pola identik `LeadAssignSelect.tsx` di CRM.
- Breadcrumb tampil judul listing (bukan slug mentah), lewat `SetBreadcrumbLabel` — pola yang sama seperti CRM.

## Watermark Foto (28 September 2026)

Setiap foto yang diupload lewat `uploadListingPhoto.ts` (baik dari form Tambah Listing maupun halaman Detail) otomatis dikasih watermark logo Yohan.AI di tengah, sebelum diupload ke Storage. Implementasi murni **Canvas API bawaan browser** (`src/lib/property/watermarkPhoto.ts`) -- tidak nambah dependency npm apa pun. Pakai `logo-dark.png` (versi teks putih, dipakai header saat dark mode) dengan opacity 55% + shadow hitam, supaya tetap kebaca di foto terang maupun gelap -- **bukan** `app-icon.png` yang dipakai boot/loading screen. Kalau logo gagal dimuat atau canvas tidak didukung, foto tetap diupload tanpa watermark daripada gagal total.

## Migrasi dari Spreadsheet (28 September 2026)

**91 listing** dari spreadsheet legacy Griya Indonesia ("Listing Baru 2024 Terbaru", sheet "Input Data") dimigrasikan ke `property.listings` lewat skrip Node.js satu-kali (tidak disimpan di repo -- one-off, bukan reusable, dijalankan lokal pakai `SUPABASE_SERVICE_ROLE_KEY`). Hasil: **91/91 listing masuk, 285/285 foto berhasil diunduh ulang dari Google Drive dan diupload ke Storage bucket `properties`** (jauh lebih baik dari ekspektasi -- log AutoCrat lama di spreadsheet sempat mencatat 55/91 link foto rusak, ternyata sebagian besar sudah bisa diakses lagi sekarang).

**Keputusan yang diambil sebelum migrasi (dikonfirmasi eksplisit ke Yohan):**
- **Kepemilikan (`assigned_to`):** semua 91 listing di-assign ke admin dulu (bukan dipetakan ke 9 agen berbeda di data lama, cuma 2 yang punya akun platform sekarang -- Yohan & Ramlan).
- **`contact_phone`:** diseragamkan ke nomor kantor Griya Indonesia (`0821-5041-5012`), bukan nomor pribadi pemilik properti yang ada di data lama.
- **Data pribadi pemilik** (KTP, tanggal lahir, pekerjaan, alamat, No. HP pemilik) -- **sengaja tidak diimpor sama sekali**, tidak ada tempat/fitur untuk itu di schema sekarang.
- **Foto:** dicoba migrasikan yang linknya masih valid (bukan skip) -- hasilnya 100% berhasil dari yang dicoba.

**Masalah data yang ditemukan & ditangani saat migrasi:**
- **Bug parsing harga:** 1 listing ("Tanah Ruko Tepi Jalan Pak Benceng Pontianak") sempat salah jadi `Rp 16` karena harga aslinya ditulis teks "1.6 M per kapling" (bukan format angka standar) -- parser digit-only salah menafsirkannya. Diperbaiki manual jadi `Rp 1.600.000.000` setelah ditemukan lewat pengecekan visual di `/properties`, bukan cuma percaya laporan "0 gagal" dari skrip migrasi.
- **Luas tanah/bangunan ambigu** (7 nilai, mis. "36, 45, 60" untuk kompleks multi-tipe, "65+") -- sengaja dikosongkan sebagai angka, teks aslinya tetap masuk deskripsi supaya tidak ada data yang salah tebak.
- **Listing kemungkinan duplikat:** ditemukan 9 kelompok (20 listing) dengan pemilik+harga identik tapi judul/baris berbeda di spreadsheet asli (kemungkinan disubmit ulang via Google Form) -- **sengaja tidak dihapus otomatis**, karena sebagian bisa jadi memang listing berbeda dalam satu kompleks. Perlu ditinjau manual oleh Yohan.
- Kolom pipeline `customer.leads.status`-style yang serupa tidak ada masalah di sini karena `property.listings` tidak punya kolom pipeline seperti itu -- field `status` (available/booked/sold/hold) di metadata semuanya di-default `"available"`, belum ada sumber data yang bisa dipercaya untuk status sebenarnya (data spreadsheet dari 2024, sebagian mungkin sudah terjual).

## Kelola Kategori (`/properties/categories`)

Diakses lewat tombol "Kelola Kategori" di header halaman `/properties`. Form tambah kategori (nama + deskripsi opsional) di atas, daftar kategori aktif dengan tombol Edit (inline) dan Hapus di bawahnya. Hapus memakai **soft delete** (kolom `deleted_at`), bukan DELETE asli -- kategori yang dihapus hilang dari dropdown listing tapi listing lama yang masih memakainya tetap menampilkan namanya (lihat `getListings.ts`, join kategori tidak filter `deleted_at`). Kategori terhapus bisa dilihat & dipulihkan lewat toggle "Tampilkan kategori terhapus" di bagian bawah halaman. Nama kategori duplikat (termasuk yang cocok dengan kategori yang sudah dihapus, karena constraint `UNIQUE(name)` di database tidak terkecuali baris terhapus) ditolak dengan pesan error yang jelas.

### Download JPG/PDF — dihentikan sementara

Tombolnya masih ada di kode (`PropertyExportButtons.tsx`, `PropertyFlyer.tsx`, `src/lib/property/exportFlyer.ts` — capture DOM ke canvas pakai `html2canvas`, lalu `jspdf` untuk versi PDF, full client-side) tapi **pengembangannya dihentikan** setelah 2 iterasi desain ditolak Yohan ("jauh dari harapan"). Akar masalah: kode mengasumsikan foto yang diupload adalah foto polos properti, padahal foto sungguhan yang dipakai Yohan sudah berupa desain promosi jadi (post Instagram dengan teks/denah sendiri) — overlay teks otomatis & crop kolase paksa jadi tabrakan/motong konten penting. Sempat dieksplorasi juga pakai Canva (tersambung ke sesi chat), tapi akun Canva Yohan belum punya Brand Template/Brand Kit, dan koneksi Canva di sesi chat terpisah dari kemampuan aplikasi production — butuh setup terpisah kalau mau dilanjutkan. Detail lengkap: memory `property-flyer-autogen-failed`. **Jangan desain ulang flyer ini lagi tanpa alasan/arahan baru dari Yohan.**

# Current Limitations

- AI Recommendation belum aktif — menunggu AI Foundation.
- **9 kelompok (20 listing) kemungkinan duplikat** dari hasil migrasi spreadsheet (28 Sep 2026) belum ditinjau manual -- lihat daftar lengkap di percakapan/riwayat sesi, atau query ulang lewat `description` yang mengandung `[Migrasi dari spreadsheet, GDI/2026/<n>]`.
- **Storage foto masih di Supabase** (free tier 1GB, saat ini terpakai ~100MB dari migrasi 91 listing + listing manual) -- dibahas opsi pindah ke Cloudflare R2 (10GB gratis, egress selalu gratis) tapi belum diputuskan/dieksekusi, lihat catatan di `docs/status.mdx`.
- Belum ada UI untuk memulihkan listing yang sudah dihapus (soft delete) -- beda dari kategori yang sudah punya toggle "Tampilkan terhapus".
