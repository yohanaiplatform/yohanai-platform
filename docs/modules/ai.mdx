# AI Intelligence Module

AI Intelligence adalah inti pembeda Yohan.AI dibandingkan CRM properti tradisional.

Modul ini bertugas menganalisis perilaku calon pembeli, menghasilkan insight, memberikan rekomendasi tindak lanjut, dan membantu agen mengambil keputusan berdasarkan data.

AI tidak menggantikan agen, tetapi bertindak sebagai **co-pilot** yang membantu meningkatkan produktivitas dan peluang closing.

## Diskusi Arsitektur AI Agent Otomatis (27-28 September 2026) — belum ada kode, murni keputusan arah

Yohan minta segera mulai follow-up manual untuk "Lead Beku" (Cold, 966 lead) dan "Follow-up Backlog" (Hot/Warm, 634 lead), tapi **ditunda 1-2 hari** sampai nomor WA produksi (Griya Indonesia) disambungkan ke Kapso — supaya follow-up yang dikerjakan langsung pakai nomor asli, bukan sandbox. Sambil menunggu itu, dibahas dulu rancangan AI Agent yang nanti mengotomasi follow-up + update status funnel-nya.

**1. Riset dokumentasi era ChatGPT/Qwen (`project-docs/`, arsip pra-Claude).** Yohan yakin arsitektur "beberapa AI Agent" sudah pernah ditetapkan dulu. Ditemukan satu dokumen nyata: `project-docs/archive/17 Juli 2026/AGENTS.md` (v1.8) — 10 AI Agent dengan Purpose/Responsibilities/Input/Output masing-masing (Executive Intelligence, **CRM Intelligence** — output Hot/Warm/Cold classification, **Conversation Intelligence** — sentiment/buying signal/objection detection, Property Intelligence, Marketing Intelligence, Knowledge, Workflow — platform n8n, **Notification** — kirim WA/Email untuk reminder/follow-up, Reporting, Learning). **Tapi tidak pernah ada desain yang menyatukan 3 agent itu (CRM + Conversation + Notification) jadi satu alur "kirim WA follow-up → baca balasan → otomatis update status funnel"** — itu, dan detail 2 trigger yang diketahui rusak (`batchDetectConsumerIntent`, `batchExtractBudget`, error rate 100% per catatan `AGENTS.md`), nol referensi di seluruh `project-docs/`. Kemungkinan cuma pernah dibahas lisan di sesi ChatGPT yang tidak sempat ditulis, atau ada di kode Apps Script asli (di luar repo ini) yang belum dicek ulang sesi ini.

**2. Keputusan: bangun tanpa n8n.** Rancangan asli pakai n8n sebagai "Workflow Agent" untuk orkestrasi. Diputuskan tidak perlu, karena kebutuhan orkestrasinya sudah tercakup pola yang sudah ada di project ini:
   - Trigger pesan WA masuk — sudah ada, `POST /api/whatsapp/webhook` jadi titik masuk (setara "Customer Message" di diagram lama).
   - Trigger terjadwal (mis. follow-up otomatis untuk lead yang sudah lama tak tersentuh) — dipakai pola yang sudah terbukti jalan di project ini: GitHub Actions scheduled workflow (persis seperti `.github/workflows/supabase-keepalive.yml`), memanggil satu API route.
   - Logika "interpretasi balasan → keputusan → tulis status → balas" — dirangkai sebagai pemanggilan fungsi biasa di dalam handler webhook (panggil LLM → update `customer.leads` → panggil `sendWhatsAppText()`), bukan node-node visual terpisah.
   - Kalau nanti tetap butuh visual/no-code builder (supaya Yohan bisa utak-atik alur sendiri tanpa minta kode), alternatifnya Workflow/Agent bawaan **Kapso** (sudah jadi platform yang dipakai), bukan n8n — tidak menambah service baru untuk di-host & dijaga.

**3. Pertanyaan baru: multi-tenant untuk masa depan (dibahas, belum diputuskan arahnya, cuma dipetakan opsinya).** Lihat detail lengkap perbandingan **Model A (SaaS multi-tenant sungguhan)** vs **Model B (duplikasi instance per pelanggan)** di `docs/modules/crm.mdx` bagian "Multi-Tenant untuk SaaS". Artinya **sisi Kapso/WhatsApp bukan penghalang** untuk Model A kalau nanti dipilih — penghalang aslinya tetap murni skema database (`tenant_id` + RLS di semua tabel domain), belum berubah dari keputusan penundaan 26 September.

**4. Pertanyaan baru (28 Sep, malam): kalau lead minta foto properti saat di-follow-up AI via WA, dikirim foto asli atau cuma link?** Dicek langsung ke dokumentasi resmi Kapso (`docs.kapso.ai/api/meta/whatsapp/messages/send-a-message`) — API WhatsApp (via Meta Cloud API, yang dipakai Kapso) **mendukung kirim gambar langsung pakai URL publik**, tidak wajib upload dulu:
```json
{ "messaging_product": "whatsapp", "to": "...", "type": "image", "image": { "link": "<url>", "caption": "..." } }
```
Karena `photo_urls` di `property.listings.metadata` **sudah berupa URL publik Supabase Storage**, AI Agent nanti (begitu dibangun) bisa langsung kirim foto asli inline di chat WA (bukan cuma link teks yang harus diklik) — tinggal panggil endpoint kirim pesan Kapso dengan `type: "image"` dan `image.link` = salah satu `photo_urls`. Belum ada kode ditulis (AI Agent masih di-hold), ini murni temuan riset untuk referensi Task 015 nanti. **Catatan penting:** logika ini WAJIB cek flag `metadata.hidden` dulu sebelum mengirim/mereferensikan foto atau data listing manapun ke lead — lihat "Sembunyikan/Tampilkan Listing" di `docs/modules/property.mdx`.

# Current Features

## AI Insight Panel (`AIInsightPanel.tsx`)

Tampil di Dashboard, di-populate dari `getDashboardInsights.ts`. Isinya campuran:

- **Follow-up Backlog** — nyata, dihitung dari `customer.leads` (lead Hot/Warm yang belum di-follow-up >48 jam). Bisa diklik, mengarah ke `/crm?temperature=hot,warm`.
- **Lead Beku** (27 September 2026) — nyata, dihitung dari lead ber-Temperature **Cold** yang belum tersentuh sejak komunikasi terakhir lebih dari **30 hari** (`FROZEN_LEAD_OVERDUE_DAYS`), yaitu **966 dari 1280** lead Cold. Bisa diklik, mengarah ke `/crm?temperature=cold`.
  - **Percobaan pertama SALAH, dikoreksi Yohan:** awalnya ditarget ke Temperature "Closing" (39 lead) dengan asumsi "sudah dekat closing tapi mandek, berisiko batal". Ternyata **salah total** -- Yohan mengonfirmasi lead berkategori Closing di data ini **sudah closing/booking, bahkan sebagian sudah akad dan menempati rumahnya**. Bukan "menuju closing", tapi "sudah selesai". Detail arti Temperature yang benar: lihat memory `lead-temperature-semantics`.
  - **Arah yang benar (setelah dikoreksi):** Hot/Warm sudah dicakup Follow-up Backlog (ambang 48 jam, urgensi tinggi/jangka pendek), jadi Cold jadi pelengkap alami untuk lead jangka panjang yang berpotensi masih bisa diaktifkan lagi. Volume besar (966) sengaja tidak dipangkas lebih lanjut -- itu justru temuannya: pool lead dingin yang belum pernah direaktivasi sejak data di-backfill.
  - Sama seperti Follow-up Backlog, `href` cuma filter berdasar Temperature (`?temperature=cold`, total 1280), bukan subset 966 yang overdue secara spesifik -- klik kartu membawa ke daftar Cold penuh, bukan daftar 966 yang persis sama. Trade-off yang sama sudah ada di Follow-up Backlog, cuma baru kelihatan sekarang karena Cold tidak 100% overdue (beda dari Hot/Warm yang kebetulan 100%).
- **Buyer Behavior Insight** — masih contoh ilustratif (`isPlaceholder: true`), ditandai badge "Segera hadir -- belum aktif" di UI, bukan dihapus supaya gampang dikembalikan begitu ada penggantinya (butuh data page-view/klik yang belum dikumpulkan platform).

# Database

Current Sources

- `customer.leads` (metadata JSONB) — sumber utama, volume cukup (ribuan baris), dipakai Follow-up Backlog
- `chat.conversations`/`chat.messages` — schema ada dan sudah dipakai live chat CRM, tapi baru **16 baris** (sandbox Kapso, nomor produksi belum disambungkan) — belum cukup untuk insight dari isi percakapan
- `property.listings`

`customer.activities` **tidak ada** di database (dicek 27 September 2026, `information_schema.tables` schema `customer` cuma berisi `contacts`/`lead_sources`/`leads`/`notes`) — dihapus dari daftar ini, sebelumnya cuma aspirasi yang belum pernah dibangun.

**Catatan penting soal field mana yang benar-benar "hidup" di `customer.leads`** (ditemukan 27 September 2026 saat riset Lead Beku): kolom pipeline `status` (`new`→...→`won`/`lost`) nyaris tidak pernah dipakai -- 1966 dari 1969 lead masih `new`, cuma 3 `contacted`. Field yang benar-benar mencerminkan progres lead adalah `metadata->>status_funnel_awal` (ditampilkan sebagai **"Temperature"** di UI CRM: Hot/Warm/Cold/Closing/Batal, editable lewat `LeadEditableFields`) -- meski nama kolom aslinya "awal" (initial), field ini yang dipakai aktif, bukan `status`. `customer.notes` (catatan berwaktu) juga masih 0 baris (fitur baru 26 Sep). **Kalau mau bangun insight baru dari data lead, pakai `status_funnel_awal`/metadata, jangan asumsikan kolom `status` mencerminkan kondisi lead yang sebenarnya.**

**Jangan asumsikan arti kategori Temperature dari namanya saja** -- khususnya "Closing" **BUKAN** "menuju closing/berisiko batal", tapi **sudah closing/booking/akad** (dikonfirmasi Yohan 27 September 2026, lihat memory `lead-temperature-semantics`). Urutan prioritas follow-up yang benar: Hot/Warm (mendesak) → Cold (jangka panjang, reaktivasi) → Closing/Batal (tidak perlu follow-up, sudah selesai/mati).
