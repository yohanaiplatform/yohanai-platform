# Current Focus

## Priority 1

Authentication Stabilization — Selesai secara teknis (Google OAuth + Email/Password). Facebook Login dibatalkan permanen.

Target:

- Google OAuth Login & Register — ✅ Confirmed jalan di production
- Forgot Password — ✅ Fixed & confirmed (kini via Resend SMTP, sebelumnya Gmail App Password)
- Register (email) & Email Verification — ✅ Confirmed jalan end-to-end
- Profile Page dummy data — ✅ Fixed, fetch data real dari `auth_ext.profiles`
- **Facebook Login — ❌ Dibatalkan (bukan sekadar ditunda).** Meta menolak Business Verification karena dokumen legal usaha (NIB) terdaftar atas nama usaha pribadi Yohan, sedangkan "YohanAI" adalah brand yang berada di bawah naungan usaha tersebut — mismatch nama legal ini membuat verifikasi otomatis Meta terus gagal meski dokumen sudah benar formatnya. Diputuskan tidak worth effort untuk dikejar lebih lanjut; Google OAuth + Email/Password dianggap cukup untuk kebutuhan login user. Sudah dibersihkan penuh dari codebase: `FacebookButton.tsx` dihapus, referensi di `LoginForm.tsx` & `RegisterForm.tsx` dihapus, provider Facebook di Supabase Authentication dimatikan (toggle off).
- Privacy Policy & Data Deletion pages — ✅ Dibuat, sekarang juga mencantumkan nama legal usaha
- Email domain `@yohanai.id` — ✅ Fixed. Root cause: domain `yohanai.id` (DNS dikelola Cloudflare, terhubung ke Vercel untuk web) tidak punya **MX Record** sama sekali, sehingga semua email masuk ke `admin@yohanai.id` (termasuk kode verifikasi Meta) tidak pernah sampai. MX Record ditambahkan mengarah ke `pangulubao.iixcp.rumahweb.net`, terverifikasi jalan via MXToolbox dan email masuk sukses diterima.
- **SMTP outbound (auth emails)** — ✅ Migrasi dari Gmail personal ke **Resend**. Password SMTP `admin@yohanai.id` di cPanel juga sudah diperbaiki sebagai langkah awal sebelum migrasi. Domain `yohanai.id` diverifikasi di Resend dengan subdomain khusus `send.yohanai.id` (memakai MX & TXT terpisah), sehingga email masuk existing di `yohanai.id` (via rumahweb) tidak terganggu. Supabase Authentication → SMTP Settings sudah dikonfigurasi ke `smtp.resend.com` (port 465). Tested end-to-end via flow Forgot Password — email diterima langsung di Focused Inbox (bukan Spam) pada percobaan pertama.
- **SPF, DKIM, DMARC untuk `yohanai.id`** — ✅ Selesai. SPF & DKIM ter-setup otomatis lewat proses verifikasi domain Resend (`send.yohanai.id`). DMARC record (`_dmarc.yohanai.id`, `v=DMARC1; p=none`) ditambahkan manual di Cloudflare, mode monitoring (`p=none`) untuk tahap awal.
- **Supabase Free Tier auto-pause mitigation** — ✅ Selesai. Dibuat GitHub Actions scheduled workflow (`.github/workflows/supabase-keepalive.yml`) yang ping endpoint `/auth/v1/admin/users` (pakai `service_role` key) tiap 3 hari untuk reset timer inactivity Supabase (batas asli: 7 hari tanpa aktivitas query database). Workflow juga fail eksplisit + kirim notifikasi GitHub kalau ping gagal, bukan silent fail.

Semua menggunakan data Supabase.

## Priority 2

Edit Profile Feature — Fungsional end-to-end, tervalidasi. Sisa 2 item kecil sebelum ditutup penuh.

Target:

- **Migration `001_edit_profile_schema.sql`** — ✅ Selesai (Bagian 1–5): `core.business_roles` (4 role), 4 tabel `wilayah_provinsi/kabupaten/kecamatan/desa`, kolom baru `auth_ext.profiles` (`business_role_id`, `address_line`, `wilayah_desa_id`, social media URLs, `role_details` JSONB), tabel `profile_completeness_rules` (table-driven, dengan UNIQUE constraint + dukungan conditional field), function RPC `check_profile_completeness()` (dengan `REVOKE`/`GRANT` eksplisit).
- **Seed data wilayah** — ✅ Selesai. Dataset `cahyadsn/wilayah` diparse & divalidasi silang dengan angka resmi (38 provinsi, 514 kab/kota, 7.285 kecamatan, 83.762 desa/kelurahan — cocok persis), diimport via CSV ke 4 tabel wilayah dengan 0 baris yatim (FK integrity bersih).
- **`WilayahSelector.tsx`** (cascading dropdown Provinsi → Kabupaten → Kecamatan → Desa) — ✅ Selesai & jalan. Query per-level (bukan fetch semua 83rb baris sekaligus), resolve mundur otomatis untuk mode edit, empty state eksplisit.
- **`EditProfileForm.tsx`** — ✅ Selesai & jalan. Field wajib dibaca dari `profile_completeness_rules` (table-driven, bukan hardcode), field kondisional (mis. No. Sertifikat Broker) muncul/hilang otomatis berdasar `depends_on_field_key`, progress bar Tier 1 & Tier 2 real-time dari RPC.
- **Debugging infrastruktur yang ditemukan selama development** — ✅ Selesai, 3 root cause tersolusi:
  1. Schema `auth_ext`, `core`, `customer`, `chat`, `property` belum ter-expose di Data API Settings (cuma `public` + `graphql_public` aktif) — sudah ditambahkan semua.
  2. `GRANT SELECT/UPDATE` belum diberikan ke role `authenticated` untuk `auth_ext.profiles` dan `core.business_roles` (RLS policy sudah benar, tapi grant dasar di bawahnya belum ada — dua lapisan berbeda di Postgres).
  3. CSS variable `--popover`/`--popover-foreground` tidak pernah didefinisikan di `tokens.css` project, menyebabkan semua dropdown dari komponen Select (shadcn/Base UI) tampil transparan/tembus pandang — sudah ditambahkan.
- **Twilio Verify (Phone provider)** — ⏸️ **Sengaja ditunda.** Yohan masih tahap trial/testing, belum siap upgrade ke akun Twilio berbayar. Konsekuensi: rule Tier 1 `phone_confirmed_at` akan selalu tampil "belum lengkap" sampai Twilio aktif — ini expected, bukan bug. Rencana resume saat sudah butuh volume user besar / mendekati go-live.
- **Upload foto profil (kamera/galeri/Google Drive)** — ⏳ Belum dikerjakan. Saat ini `avatar_url` masih berupa input teks URL manual. Butuh Supabase Storage bucket + policy + integrasi picker, direncanakan sebagai peningkatan terpisah setelah item di bawah ini selesai.
- **Keputusan "System Information" di Profile page** — ⏳ Perlu keputusan Yohan: hapus total, atau sembunyikan kondisional (cuma tampil untuk `role_id` admin/super_admin). Saat ini tampil ke semua user termasuk detail environment/build — berpotensi bocor info internal.
